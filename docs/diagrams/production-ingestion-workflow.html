Architecture · Diagram Design

Production competitor ingestion

Two resolution paths after the worker reads the message: competitor_lst empty (Case A) vs filled (Case B). Both paths reunite on a URL set, then fan out or process one competitor.

INPUT SCHEMA

SQS message body

{
  "company_domain_id": "marketingeye.com.au",
  "competitor_lst": ["https://…"] | null,
  "host": "dev" | "prod"
}

company_domain_id = client tenant · empty/null competitor_lst → Case A · omitted host defaults to dev.

CASE A · EMPTY

competitor_lst is null or []

Do not invent URLs. Read RM Mongo by message host: account_company → Primary strategy_strategy → non-blank competitors_client.website values. No match / no Primary / zero URLs → acknowledge and skip.

CASE B · FILLED

competitor_lst has entries

Skip RM strategy lookup. Drop malformed URLs, dedupe the rest. The surviving list is the URL set for routing — same merge point as Case A.

AFTER BOTH CASES

Same routing rules

0 → skip · 2+ → fan-out to SQS · 1 → discover or snapshot that competitor, then DynamoDB / RM writes.
