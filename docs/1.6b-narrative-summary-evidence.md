## Stored-baseline contamination follow-up

The latest real (non-simulated) Lyfe `/blog` snapshot was independently checked
through `SnapshotRepository` plus `SnapshotStorage`, rather than trusting the
change row alone. Snapshot `6aa0f93bca77d7e9aeb1c3e7`, captured at
`2026-09-09T06:14:19.429Z`, contained this exact stored tail:

```html
<section><h2>Forced narrative failure verification marker</h2><p>This content exists only to force a real change: ea4e3834d05647b09ec27bcbff27b4a2.</p></section></body></html>
```

Its `content_hash` was
`9172bb86159fccff4a6fce561577e5f895e40894ab039123c7f7a26177824ad4` and its
stored size was 67,489 bytes. This confirms the LLM narratives were accurately
describing test content baked into the real comparison baseline. The cause was
the pre-refactor `tests/live_narrative_summary_verification.py`: its forced
failure case injected that marker and called the database-backed
`MonitoringRunService`, which created an untagged real snapshot. The script now
uses in-memory repositories for every mutation and validation path.

262,654 raw characters, and no forced/verification/test markers. It was stored
as the new real baseline snapshot `6aa1448b75ac38bd8fce8d5c`, captured at
`2026-09-09T11:35:39.057Z`, with hash
`dd86739940221a0079841e786b07eddcea28fa51422b4860317b63ebb0e8dd4e`, 67,328
