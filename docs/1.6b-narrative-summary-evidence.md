# 1.6b narrative-summary and detected-URL evidence

This records the real-path verification for the narrative-summary and
detected-URL additions to 1.6b. Relevance filtering remains separately
deferred.

## Live BLOG simulation

Command:

```text
RUN_LIVE_NARRATIVE_SUMMARY=1 MONGODB_DATABASE=competitors_monitoring_test \
  python -u tests/live_narrative_summary_verification.py
```

The real Lyfe Marketing `/blog` simulation created `NEW_BLOG` change
`6aa0f923ca77d7e9aeb1c3e3`. The generated narrative was:

> The page replaces the placeholder “forced narrative” section with a new blog post titled “Mastering Short-Form Video: A Practical Guide for 2026,” including date, author, category, a video thumbnail, and structured content (three steps, ideas, and footer with tags).

The mechanical summary remained:

```text
NEW_BLOG: 40 line(s) added, 3 line(s) removed (3096 characters added, 222 removed).
```

The counting provider recorded one existing mutation JSON generation and one
structured narrative-and-URL generation. The LLM correctly returned the
tracked `/blog` page for this broad page diff; the specific-post happy path is
verified below with a real captured article link.

## Detected-URL validation cases

The same real run used a live capture from `https://www.lyfemarketing.com/blog`
and made a `NEW_BLOG` diff containing the URL and title of the real first
article link. The structured call selected the specific post URL and the
existing usable-response heuristic accepted it:

```text
change_id: 6aa0f948ca77d7e9aeb1c3e9
source_article_url: https://www.lyfemarketing.com/blog/60-30-10-rule-social-media/
detected_url: https://www.lyfemarketing.com/blog/60-30-10-rule-social-media/
domain_validation: passed
liveness_validation: passed
provider_generate_json_calls: 1
```

The expected `PAGE_UPDATE` fallback was also exercised against the live
capture with only a minor wording marker. Its URL was the tracked page and no
liveness check ran for the fallback:

```text
change_id: 6aa0f949ca77d7e9aeb1c3ea
detected_url: https://www.lyfemarketing.com/blog
liveness_calls: []
```

Validation rejected both a wrong-domain candidate and a dead same-domain
candidate. The wrong-domain candidate was rejected before liveness; the dead
candidate was checked with the existing fetch heuristic and then fell back:

```text
wrong_domain_candidate: https://example.com/ton31-wrong-domain
wrong_domain_detected_url: https://www.lyfemarketing.com/blog
wrong_domain_liveness_calls: []
dead_candidate: https://www.lyfemarketing.com/ton31-definitely-dead-url
dead_detected_url: https://www.lyfemarketing.com/blog
dead_liveness_calls: [https://www.lyfemarketing.com/ton31-definitely-dead-url]
```

## Real product URL evidence

`tests/live_product_listing_verification.py` captured the real JD Sports sale
page, proved two identical captures had the same normalized hash, and then
ran one deterministic mutation through the real monitoring orchestration. The
three persisted events were:

```text
NEW_PRODUCT     https://www.jd-sports.com.au/product/ton21-synthetic-product/sku-ton21
PRICE_CHANGE    https://www.jd-sports.com.au/product/black-adidas-originals-campus-00s-womens/19688955_jdsportsau
PRODUCT_REMOVED https://www.jd-sports.com.au/product/black-adidas-originals-adibreak-track-pants/19725563_jdsportsau
product_liveness_attempts=[]
removed_url_is_last_known=True
```

The product flow made no narrative call and no detected-URL liveness call.
The removed URL is persisted as the last-known product URL even though it may
now return 404.
